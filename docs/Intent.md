# Intent — 현재 작업

계획: `docs/superpowers/plans/2026-11-13-second-overhaul.md`

## 단계 1. 안정성·성능 (2026-11-13 시작)

1. **문제**: 복습 중 삭제된 문장을 평가하면 앱이 꺼질 수 있고, 미리 복습하면 간격이 부풀려지며, 첫 실행 때 키를 저장하면 탭이 튄다. 라이브러리·통계가 같은 전체 조회를 여러 번 메인 스레드에서 돌리고, AI 호출은 취소·재시도·오류 구분이 약하다. 출시용 빌드가 줄여지지 않는다.
2. **기대 결과**: 위 버그가 테스트로 재현된 뒤 고쳐지고, 화면은 그대로이면서 조회·계산이 줄고, AI 실패가 정확한 문구로 보이며, release 빌드가 R8로 줄어든다. 단위 테스트 407개 + 새 테스트 모두 통과.
3. **영향 범위**: `domain/Scheduler.kt`, `review/ReviewSession.kt`, `ui/review/ReviewViewModel.kt`, `MainActivity.kt`, `ui/library/*`, `data/EntryRepository.kt`, `stats/*`, `widget/*`, `reminder/*`, `ai/GeminiAiService.kt`, `AppContainer.kt`, `app/build.gradle.kts`.
4. **제약**: 화면 모양은 바꾸지 않는다(디자인은 단계 3). DB 스키마 변경은 단계 2에서 한 번에. 라이브러리 추가·버전 올리기는 승인 후.
5. **열린 질문**: 의존성 버전 올리기 승인 여부. 생각 예산·모델 고정(1-15)은 공식 모델 목록 확인 뒤 다시.

**상태(2026-11-13)**: 완료, 커밋함(f34a5c4~2826d01). 미리 복습은 "기한 전이면 지난 시간만 인정"으로 고쳤다(FSRS는 단계 2). 테스트 428개 통과, QA는 `docs/qa-guide.md`.

## 단계 2. DB v5 + FSRS (2026-11-13)

1. **문제**: 일정이 SM-2라 늦게·일찍 복습한 시간을 제대로 반영하지 못하고, 다음 단계 기능(단어 카드, 대화 맥락, 사람·나라 태그, 문법 약점, 노션)을 담을 칸이 없다. 조회에 필요한 인덱스도 없다.
2. **기대 결과**: v4 데이터가 그대로 v5로 오르고, FSRS가 실제 지난 시간으로 간격을 정하며, 기억 목표를 고를 수 있다.
3. **영향 범위**: `data/*`(엔터티·마이그레이션·DAO·백업), `domain/Scheduler.kt`, `review/ReviewSession.kt`, 설정.
4. **제약**: 마이그레이션은 테스트 먼저, 데이터 삭제 금지. 스키마 변경은 이번 한 번.
5. **열린 질문**: 없음.

**상태**: 완료, 커밋함(bfe489a, e72579f). 테스트 432개 통과.

## 단계 3. 새 브랜드·정보 구조·UX (2026-11-13)

1. **문제**: 기본 M3 보라라 정체성이 없고, 복습 첫 화면이 비며, 통계·설정이 깊이 숨어 있다. 복습 화면 파일이 너무 크다.
2. **기대 결과**: "따뜻·선명" 브랜드와 말풍선 표지, 앱을 열면 오늘 할 일이 한눈에, 복습은 대화처럼, 목표 달성에 축하.
3. **영향 범위**: `ui/theme/*`, `ui/today/*`(새), `ui/review/*`(나눔), `MainActivity.kt`, `ui/components/*`, 번역·라이브러리·설정·통계 화면 일부.
4. **제약**: 폰트는 승인받은 Fredoka만. 새 라이브러리 없음.
5. **열린 질문**: 시작 속도 개선(WorkManager 지연 초기화, 베이스라인 프로필) 승인 여부.

**상태**: 완료, 커밋함(de2f1f4, cd30f32). 테스트 433개 통과, 에뮬레이터 화면 확인.

## 단계 4. 들어오는 길·맥락·태그 (2026-11-14)

1. **문제**: 첫 실행이 설정 화면으로 바로 떨어지고, 한국어 공유는 오류로 막히며, 카톡 대화를 붙여 넣으면 이름·시각이 문장에 섞인다. 누구와 나눈 말인지, 어떤 대화였는지 남지 않는다.
2. **기대 결과**: 안내를 따라 키를 넣고 예시를 번역해 보고, 대화를 붙여 넣으면 친구와 맥락이 함께 저장된다.
3. **영향 범위**: `domain/MessageSplit.kt`·`People.kt`, `ui/translate/*`, `ui/onboarding/*`(새), `data/EntryRepository.kt`·`AppDao.kt`, 복습 채점·상세, 설정.
4. **제약**: 스키마는 v5 그대로.
5. **열린 질문**: PROCESS_TEXT 결과 돌려주기(보류).

**상태**: 완료, 커밋함(fce4905, cb515f7). 테스트 453개 통과.

## 단계 5. 배우는 기능 (2026-11-14)

1. **문제**: 첨삭은 AI가 답을 바로 줘서 스스로 깨닫는 과정이 없고, 내가 어떤 문법에 약한지 알 길이 없다.
2. **기대 결과**: 힌트를 받으며 스스로 고쳐 쓰고, 써 보기·복습·보낼 말에서 모인 기록으로 약한 문법을 보고 바로 연습한다.
3. **영향 범위**: `domain/Grammar.kt`(새), `ai/*`, `ui/translate/*`(써 보기·단어 카드), `review/ReviewSession.kt`, `stats/GrammarStats.kt`(새)·`StatsScreen.kt`, 오늘 화면, 라이브러리 상세.
4. **제약**: 문법 목록은 고정(언어별 24개). 스키마 v5 그대로.
5. **열린 질문**: 실제 AI가 힌트 단계에서 정답을 흘리지 않는지는 사람 확인이 필요하다.

**상태**: 완료, 커밋함(d01ff37, a2a7935). 테스트 464개 통과.

## 단계 6. 노션 내보내기·백업 (2026-11-14)

1. **문제**: 저장한 문장을 노션에 모을 수 없고, 앱 데이터가 휴대폰 백업에 들어가지 않아 폰을 바꾸면 사라진다.
2. **기대 결과**: 고른 문장을 노션 데이터베이스에 한 줄씩 보내고(다시 보내면 고침), 문장·설정은 구글 백업과 매주 자동 백업 파일로 지킨다.
3. **영향 범위**: `notion/*`(새), `settings/AutoBackup.kt`(새)·`SettingsRepository.kt`, 설정·라이브러리 화면, `AppContainer.kt`, 매니페스트·백업 규칙.
4. **제약**: 새 라이브러리 없음(OkHttp, DocumentsContract). 토큰은 앱에만.
5. **열린 질문**: 실제 노션 데이터베이스(사람 확인), 노션 데이터베이스를 대신 만들어 줄지.

**상태**: 완료, 커밋함(5ad6b52, ac6501c, 1d4002f). 테스트 476개 통과.

## 단계 10. 디자인 다시 잡기: "AI 티" 걷어내기 (2026-11-14)

1. **문제**: 단계 3의 보라 주색(`#5B2EE0`)과 보라 통판·색 띠·반짝이·둥근 카드 쌓기가 AI가 만든 화면처럼 보인다(사용자 지적, 웹 조사로 확인).
2. **기대 결과**: "종이 노트 + 빨간 펜" 방향. 큰 면은 종이·먹, 색은 뜻이 있을 때만 쓴다(빨간 펜=틀림·삭제, 형광펜=거의 맞음·핵심 표현·폴더, 초록=맞음). 외국어 문장은 세리프(Literata). 라이트·다크 모두 대비 4.5:1 이상.
3. **영향 범위**: `ui/theme/*`, `ui/components/*`(구역·막대·말풍선·도장), 오늘·라이브러리·번역·써 보기·복습 화면, 앱 아이콘·위젯·창 배경 색. 화면 구조와 흐름은 그대로 둔다.
4. **제약**: 새 글꼴 Literata(OFL, 170KB×2)를 추가하고 Fredoka는 지운다. 단계 3의 "폰트는 Fredoka만" 제약을 대신한다. 새 라이브러리는 없다.
5. **열린 질문**: 실기기에서 보는 디자인 취향, 목표 달성 도장 화면(에뮬레이터에서 띄우지 못함).

**상태**: 완료. 테스트 489개 통과. 계획: `docs/superpowers/plans/2026-11-14-design-refresh.md`.

## 단계 11. impeccable로 디자인 근본부터 다시 (2026-11-14)

1. **문제:** 단계 10의 "종이 노트 + 빨간 펜"(크림 바탕·세리프·주홍)도 AI가 고르는 "단정한 기본값"이었다. 사용자가 impeccable 스킬로 근본부터 다시 하자고 했다.
2. **기대 결과:**
   - impeccable 절차를 따른다: init(PRODUCT.md) → 세계 후보 7개 → 주사위(concept-seed) → 결정 페이지에서 사용자 선택 → 방향 계약 → 구현 → 따로 띄운 리뷰어의 판정 → DESIGN.md.
   - 사용자가 고른 세계는 "출국장: 출발 안내판과 탑승권"이다.
     - 라이브러리는 출발 안내판(시간·목적지·편·상태, 익힌 단계, 다음 복습까지의 거리)이다.
     - 번역·써 보기·복습은 탑승권(경로 머리띠, 절취선 아래 떼는 칸)이다.
3. **영향 범위:** `ui/theme/*`, `ui/components/{Board,Bubble,GoalBoard,DayBars}.kt`, 라이브러리·번역·써 보기·복습·오늘 화면, `MainActivity` 골격, `LibraryOrder`(익힌 단계), 친구 이름 검색, 아이콘·위젯 색, 번들 글꼴 Roboto Condensed.
4. **제약:**
   - Operate 화면이라 세계는 글꼴·색·밀도·대표 동작만 빌리고, 조작은 Material 3 표준을 쓴다.
   - 새 글꼴(Roboto Condensed, OFL)은 사용자가 승인했다.
   - 새 라이브러리는 없다.
5. **열린 질문:** 실기기 취향, 플랩 움직임 체감, 삼성 폰 렌더링.

**상태:** 리뷰어 최종 판정 ship, 코드 리뷰 지적 9개 반영. 테스트 491개 통과. 기록: `PRODUCT.md`, `DESIGN.md`, `.impeccable/design.json`, `.impeccable/surfaces/`.
