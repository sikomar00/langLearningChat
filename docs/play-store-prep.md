## 2. 해야 할 일

### 필수로 보이는 것
1. **targetSdk 36으로 올리기.** 보도 기준 2026-08-31부터 신규 앱·업데이트에 요구됨(Play Console 안내로 확인).
   올린 뒤 Android 16 동작 변경(예: 화면 방향·크기 조정, 뒤로가기) 영향을 **실기기에서** 확인해야 함.
2. **release 빌드 만들기**: 업로드 키 서명(키는 저장소에 넣지 않음), AAB(`bundleRelease`),
   R8 켜기. Room, kotlinx.serialization, Glance, 보안 라이브러리의 keep 규칙을 확인하고
   **릴리스 빌드로 앱을 실제로 돌려 봐야 함**(단위 테스트로는 R8 오류가 잡히지 않음).
3. **개인정보처리방침 URL**: 공개된 웹 주소가 필요. 운영자명·연락처를 채우고 호스팅 위치 정하기.
4. **데이터 보안(Data safety) 양식**: 사용자 입력 글이 Google Gemini API로 전송됨을 공유로 신고해야 하는지
   Play Console 안내로 확인. (공식 정책 문서는 서드파티 AI 연동도 공개·동의 대상이라고 함.)
5. **심사용 접근 정보**: 앱이 API 키 없이는 AI 기능을 못 쓰므로, 심사자가 쓸 **임시 키**를 앱 액세스 안내에
   제공해야 할 수 있음. 한도 제한을 둔 폐기 가능한 키를 쓸 것.

### 확인이 필요한 것 (제가 확인하지 못함)
- 생성형 AI 앱에 요구되는 **앱 안 신고·피드백 기능** 여부와 이 앱이 해당하는지.
- 신규 개인 개발자 계정의 **비공개 테스트 요건**(테스터 수, 기간)의 현재 기준.
- 콘텐츠 등급 설문, 대상 연령, 타깃 국가·언어(한국어 UI).
- 스토어 등록정보 자산(아이콘 512px, 기능 그래픽, 스크린샷). 기존 화면 캡처는 개인 대화가 없는 것만 사용.

### 제품 측면 (심사와 별개로 채택률에 영향)
- **API 키를 직접 발급해야 하는 첫 사용 장벽**이 가장 큼. 안내 3단계를 넣었지만, 일반 사용자가 이 과정을 끝낼지는 모름.
  배포 전에 주변 몇 명에게 첫 실행을 시켜 보고 어디서 멈추는지 관찰할 것.
- 호스팅 키 방식(운영자가 키를 대고 사용자는 키 없이 사용)으로 가면 비용, 남용 방지, 개인정보 처리 책임이 모두 운영자에게 생김.
  그 경우 앱 증명(App Check 등)과 서버 쪽 한도 설계가 필요하며, 이 문서의 범위 밖.

## 3. 데이터 보안 양식 초안 (확인 필요)
| 질문 | 초안 답 | 근거 |
|---|---|---|
| 운영자가 데이터를 수집하는가 | 아니오 (서버 없음) | 네트워크 호출은 사용자 키로 Google에 직접 |
| 제3자와 공유하는가 | **예**: 사용자가 입력한 글을 Google(Gemini API)에 전송 | 코드: `GeminiAiService` |
| 공유 데이터 유형 | 사용자 생성 콘텐츠(메시지/문장) | 위와 같음 |
| 전송 중 암호화 | 예 (HTTPS) | `GEMINI_BASE_URL`이 https |
| 삭제 요청 수단 | 앱 삭제·앱 안 삭제 / Google 계정 | 방침 7항 |
| 선택 사항인가 | 예: AI 기능을 쓸 때만 전송 | 키를 넣지 않으면 전송 없음 |
