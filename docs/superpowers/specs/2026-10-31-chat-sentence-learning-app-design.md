# 채팅 문장 학습 앱 설계

작성일: 2026-10-31

## 1. 목적

한국어 화자인 사용자가 헬로톡, 왓츠앱 등에서 외국인 친구(영어, 스페인어)와 주고받은 문장을 저장하고, 그 문장으로 직접 써 보며 복습해서 표현을 자기 것으로 만드는 안드로이드 앱.

### 성공 기준
- 받은 말은 번역과 설명을 보고 저장하고, 보낼 말은 후보를 받아 복사한 뒤 자동 저장된다.
- 저장된 문장을 한국어, 영어, 스페인어 중 한 언어로 보여 주고, 사용자가 한국어가 아닌 다른 언어(영어 또는 스페인어)로 직접 쓰면 AI가 채점하고 교정한다.
- 간격 반복 일정에 따라 매일 복습할 카드가 나온다.
- 비용은 무료 AI API 한도 안에서 해결하고, 한도 초과나 오프라인에서도 복습은 계속된다.

### 사용자와 가정
- 사용자는 본인 한 명이고, 기기는 갤럭시 S25(One UI 9.0)이다.
- 서버, 계정, 클라우드 동기화는 없다.

## 2. 범위

### MVP에 포함
- 번역 탭: 받은 말 / 보낼 말 두 모드
- 라이브러리 탭: 저장 문장 목록, 검색, 필터, 태그, 편집
- 복습 탭: 간격 반복, 직접 쓰기, AI 채점, 셀프 채점 대체
- 설정 탭: API 키, 기본 언어, 내보내기와 가져오기(JSON)

### MVP에서 제외 (다음 단계)
- 홈 화면 위젯(복습 카드, 빠른 입력). 위젯에는 텍스트 입력 칸을 넣을 수 없으므로, 탭하면 작은 입력 창이 뜨는 방식으로 만든다.
- 공유 메뉴로 문장 받기
- 연속 학습(streak) 기록, TTS 발음 듣기
- 클라우드 동기화

위젯은 스케줄러와 데이터 계층을 그대로 쓸 수 있도록 MVP에서 화면 로직과 분리해 둔다.

## 3. 기술 구성

- 플랫폼: 네이티브 안드로이드, Kotlin + Jetpack Compose
- 저장: Room(로컬 DB), 설정은 DataStore, API 키는 암호화된 저장소
- AI: Gemini API 무료 티어(Flash 계열). 모델 이름은 설정에서 바꿀 수 있다.
- 무료 한도 수치는 자료마다 달라서 구현 전에 Google 공식 문서로 확인한다.

## 4. 화면

하단 탭 4개. 첫 실행 때 API 키가 없으면 설정 화면으로 안내한다.

### 4.1 번역 탭
- **받은 말**: 메시지를 붙여넣으면 원어를 감지하고 한국어 번역과 핵심 표현 설명을 보여 준다. 저장 버튼으로 라이브러리에 넣는다.
- **보낼 말**: 한국어 입력과 대상 언어(영어 또는 스페인어)를 고르면 후보 2~3개와 각 뉘앙스 설명을 보여 준다. 하나를 고르고 복사하면 자동으로 저장된다.

### 4.2 라이브러리 탭
- 문장 목록, 검색, 언어와 태그 필터
- 상세 화면에서 원문, 번역, 설명, 복습 상태를 보고 직접 고칠 수 있다.

### 4.3 복습 탭
- 오늘 복습할 카드 수를 보여 준다.
- 카드 흐름: 한국어, 영어, 스페인어 중 한 언어로 출제 → 한국어가 아닌 다른 언어로 직접 입력 → AI 채점과 교정 → 평가 버튼(다시, 어려움, 좋음, 쉬움)
- AI 판정이 평가 버튼의 기본 선택값을 정하고, 사용자가 바꿀 수 있다.
- 오프라인이거나 한도가 소진되면 정답을 보여 주고 스스로 채점하는 방식으로 자동 전환한다.
- 출제 언어는 한국어를 더 자주 내고, 다른 외국어 버전이 이미 있을 때만 그 언어도 후보가 된다.

### 4.4 설정 탭
- API 키, 모델 이름, 기본 언어, 하루 새 카드 수, 내보내기와 가져오기, 오늘 AI 호출 횟수

## 5. 데이터 구조

- **Entry**: id, createdAt, direction(RECEIVED, SENT), chatLang(en, es), note, tone
- **EntryText**: entryId, lang(ko, en, es), text, origin(원문, AI 번역, 사용자 수정). 처음에는 원문과 한국어 번역 두 줄이다. 다른 외국어 버전은 필요할 때 AI로 한 번 만들어 저장한다.
- **ReviewCard**: entryId, answerLang(en, es, 한국어 불가), dueAt, intervalDays, ease, reps, lapses, lastReviewedAt. 문장 하나당 카드 하나.
- **ReviewLog**: cardId, reviewedAt, promptLang, userAnswer, aiVerdict(맞음, 거의 맞음, 틀림), aiFeedback, rating
- **Tag, EntryTag**: 상대 이름과 상황 태그
- **백업**: 모든 테이블을 JSON 한 파일로 내보내고 가져온다. 이 형식이 나중에 동기화로 옮길 때의 기준이 된다.

## 6. 복습 알고리즘

스케줄러는 `next(card, rating, now) → card` 형태의 순수 함수로 분리한다. SM-2 계열로 시작하고, 나중에 FSRS로 교체할 수 있다.

- 새 카드: 간격 0일, ease 2.5
- 다시: 같은 세션에서 10분 뒤 재출제, 그다음은 1일 뒤. lapses +1, ease -0.2(최소 1.3)
- 어려움: 간격 ×1.2(최소 1일), ease -0.15
- 좋음: 첫 성공 1일, 두 번째 3일, 이후 `간격 × ease`
- 쉬움: `간격 × ease × 1.3`, ease +0.15
- 간격에 ±5% 무작위 값을 더한다.
- AI 판정의 기본 평가: 틀림 → 다시, 거의 맞음 → 어려움, 맞음 → 좋음
- 하루 새 카드 기본 10장, 복습 최대 50장. 밀린 카드는 오래된 것부터 내고 새 카드는 중간에 섞는다.

위 수치는 처음 값이며 사용하면서 조정한다.

## 7. AI 호출

`AiService` 인터페이스 뒤에 Gemini 구현체를 둔다.

1. `translateReceived(text)`: 원어 감지, 한국어 번역, 핵심 표현 설명
2. `suggestSent(koText, targetLang)`: 후보 2~3개와 뉘앙스 설명
3. `gradeAnswer(prompt, userAnswer, answerLang, reference)`: 뜻 일치 판정, 교정문, 한국어 설명. 뜻이 같으면 다른 표현도 맞음으로 인정한다.
4. `translateTo(text, lang)`: 복습용 다른 언어 버전 생성

공통 규칙
- 응답은 JSON 스키마로 받는다. 형식이 깨지면 한 번 재시도하고, 그래도 안 되면 오류로 처리한다.
- 시스템 프롬프트에 사용자가 한국어 화자라는 점을 명시한다.
- API 키는 요청 헤더로만 보낸다.
- 한도 아끼기: 다른 언어 버전은 한 번만 생성해 저장하고, 같은 입력의 번역은 캐시하며, 하루 호출 횟수를 센다.

## 8. 오류 처리

- 한도 초과(429): 한 번 짧게 재시도한 뒤, 한도 도달을 알리고 셀프 채점으로 전환한다.
- 오프라인, 시간 초과: 복습은 셀프 채점으로 전환한다. 번역 탭은 오류를 보여 주고 입력을 유지한다.
- 키 오류: 설정 화면으로 안내한다.

## 9. 테스트

- 스케줄러: 평가별 간격 계산 단위 테스트(순수 함수)
- `AiService`는 가짜 구현으로 바꿔 끼워 화면 로직과 오프라인 전환을 인터넷 없이 테스트한다.
- DB: 내보내기와 가져오기를 거친 뒤 데이터가 같은지 확인하는 테스트
- 실제 Gemini 호출은 수동으로 점검한다.

## 10. 열린 위험

- 무료 한도와 사용 가능한 모델 목록은 바뀔 수 있다. 호출부를 교체 가능하게 해서 대응한다.
- 앱을 지우면 데이터가 사라진다. 내보내기 파일로 보완한다.
